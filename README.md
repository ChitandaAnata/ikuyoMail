# ikuyoMail · 本地邮件客户端

一个跑在自己电脑上的通用邮箱客户端。用邮箱的 **IMAP / SMTP** 直连服务器，支持 QQ、163、126、Gmail、Outlook、iCloud、Yahoo、新浪、阿里云等主流邮箱，也能自定义任意服务商。

界面是三栏布局：左侧账号与文件夹、中间邮件列表、右侧阅读与回复。所有账号凭据以 AES-256-GCM 加密后只保存在本机，邮件不经过任何第三方中转。

## 快速开始

```bash
cd mailbox
npm install
npm start
```

然后打开 **http://127.0.0.1:7317** ，点「添加邮箱账号」，填邮箱地址 + 授权码即可。

懒得开终端的话，装好依赖后直接双击 **`ikuyoMail.exe`**：它自带窗口（WebView2 内核，没有地址栏和标签栏），会自己把本地服务拉起来，关掉窗口时再把服务停掉。想把它贴到屏幕顶部自动收成一条边，它也已经做了（拖到屏幕顶边、鼠标移开即可）。

没有 exe（或它跑不起来）时，双击 **`启动 ikuyoMail.bat`** 会退回旧方案：后台起服务，用 Chrome 的 `--app` 窗口打开界面。两条路的界面完全一样，只是外壳不同。详见下文「窗口、三栏与独立阅读窗口」和「打包成 exe」。

想先看看界面长什么样，可以跑演示模式（假数据，不连服务器）：

```bash
npm run demo     # http://127.0.0.1:7318
```

> 需要 Node.js 18 以上。服务只监听 `127.0.0.1`，局域网内其他设备访问不到。

## 功能

- 多账号并存，一键切换；账号列表显示未读数
- **账号可编辑**：改显示名、换授权码、改服务器地址，保存前会重新验证；也可以直接删除账号
- **账号级代理**：某个邮箱在本地网络连不上时，可以让它单独走 SOCKS5 / SOCKS4 / HTTP / HTTPS 代理，其他账号不受影响
- **连接诊断**：一键查看服务端真实口径（STATUS / EXISTS / SEARCH ALL / UIDNEXT），邮件数量对不上时能立刻定位原因
- 添加账号时用**下拉菜单选服务商**，邮箱地址拆成「用户名 @ 域名」两段，选定服务商后域名自动锁定，只需填前半段
- 文件夹浏览，收件箱 / 已发送 / 草稿 / 垃圾 / 废纸篓自动识别并排序
- 邮件列表按 UID 分页（每页 30 封），除上一页 / 下一页外，还能**直接输入页码跳转**；新邮件到达不会导致翻页错位
- **搜索**：按主题 / 发件人 / 收件人查找，中英文都行；内容是本地索引匹配的，见下文「搜索为什么不用 IMAP SEARCH」
- 阅读正文：优先渲染 HTML，外部图片默认拦截（可在设置里改成默认显示），也可看纯文本
- 内嵌图片（`cid:`）自动内联显示；附件可单独下载
- **富文本写信**：加粗 / 斜体 / 下划线 / 删除线 / 有序无序列表 / 引用 / 超链接，粘贴自动清理脚本
- **收件人自动补全**：从历史收发件里积累联系人，输入时按联系频次排序推荐，支持上下键选择
- **新邮件提醒**：后台按间隔检查收件箱，收到新邮件时在屏幕右下角弹卡片，可开关提示音；窗口不在前台时改用 Windows 系统通知
- **托盘常驻**：关掉窗口后留在通知区域继续收信，双击托盘图标重新打开，右键菜单可暂停提醒 / 立即检查 / 打开设置 / 退出（「设置…」会把已开着的窗口叫回前台并直接弹出设置面板）
- **开机自启**：设置里一键开关，登录 Windows 后静默在后台收信，不弹黑框、不写注册表
- 回复 / 转发（自动带原文引用与 `In-Reply-To`）、星标、标为未读、删除
- **列表右键菜单**：在任意一封邮件上点右键，可以设为未读 / 已读、设为待办、置顶、写备注、另存为 PDF、删除；置顶的邮件会排到列表最前面
- **另存为 PDF**：把这一封邮件的完整内容（标题、收发件人、时间、正文、附件清单）排成一页 A4 存成 PDF，而不是把主界面截下来
- 写邮件支持抄送 / 密送、多附件；发送后自动归档到「已发送」
- **三栏可调**：账号栏 / 列表 / 阅读区之间的两条分隔线能拖动改宽度（双击复位，方向键微调），阅读区可以一键收起（`F9`）
- **独立阅读窗口**：把这封邮件弹到单独窗口，主界面只剩两栏；关掉独立窗口自动回到三栏，并回到你最后看的那封
- **贴边抽屉**：主窗口贴着屏幕顶部时，鼠标移开就向上收起只剩一条边，鼠标移到顶部边缘再滑出（Windows；双击 bat 启动时生效）
- 快捷键：`C` 写邮件，`R` 刷新，`F9` 收起/展开阅读区，`Esc` 关闭弹窗
- 设置面板左下角显示当前版本（第一版是 `V1.0.0`）
- 三块各有硬下限（账号栏 190 / 列表 340 / 阅读区 440）：窗口变窄时依次压缩，碰到谁的下限就轮到下一块，全到下限后窗口就缩不动了——任何宽度下都不会把内容藏到视口外面

## 邮件列表右键菜单

在列表里任意一封邮件上点右键：

| 菜单项 | 说明 |
| --- | --- |
| 设为未读 / 设为已读 | 改的是服务器上的 `\Seen`，和网页版、手机端同步 |
| 设为待办 / 取消待办 | 本地标记，列表里打一个「☑ 待办」标签；顶部筛选条也有「待办」 |
| 置顶邮件 / 取消置顶 | 本地标记，这封邮件会排到当前页最前面，左侧一道淡金底色 + 📌 |
| 设置备注 / 编辑备注… | 本地备注，列表里显示一行摘要，打开邮件后标题下方也会显示 |
| 另存为 PDF | 把这封邮件的内容单独排成 A4 PDF，见下 |
| 删除邮件 | 移到邮箱的废纸篓（会先确认） |

置顶 / 待办 / 备注都是**纯本地状态**：存在 `data/marks.json`，不写回邮箱，换台电脑或换客户端看不到，删掉那封邮件时对应记录也会一起清掉。菜单里「置顶 / 待办 / 备注」会随当前状态变文字（已置顶的显示「取消置顶」）。

### 另存为 PDF

- 右键 → **另存为 PDF**，选好保存位置，程序会在后台把**这一封邮件**排版后打印成 A4 PDF：标题、发件人 / 收件人 / 时间、正文（图片、表格按比例缩放）、附件清单，有备注的还会附上备注。打印的是邮件本身，不是当前主界面。
- 实现方式是开一个屏幕外的小窗口加载 `public/print.html`（只渲染一封邮件的专用版式），等图片加载完再由 WebView2 的 `PrintToPdfAsync` 落盘；主窗口全程不闪、不参与打印。
- 用的是浏览器直接打开时，会打开同一个打印页并调系统打印对话框，把「目标打印机」选成「另存为 PDF」即可。
- PDF 里邮件自带的脚本一律不执行（页面带 CSP + Shadow DOM 隔离），样式和图片照常显示。

## 窗口、三栏与独立阅读窗口

### 三栏宽度

- 账号栏与列表之间、列表与阅读区之间各有一条分隔线，按住拖动即可改宽度；两侧都有最小宽度，不会被挤扁。
- 双击分隔线恢复默认宽度；用 Tab 把焦点移到分隔线上后，按 ← → 可以微调（按住 Shift 步长更大）。
- 拖过的宽度记在浏览器本地存储里，下次打开还是你调好的样子。
- 窗口变窄时列表和账号栏会临时让位给阅读区，但不会写入你的设置——窗口拉回去，宽度就回来了。
- 三块各有硬下限：**账号栏 190px、列表 340px、阅读区 440px**。列表的 340 是按「图标 + 主题 + 时间列 + 工具栏按钮」的实际需要量出来的，再窄时间就会被切掉、按钮就要换行；阅读区的 440 是按「正文左右各 22px 内边距 + 邮件里常见的两栏表格」量出来的。

### 窗口拉得很窄时会怎样

三块各有硬下限：**账号栏 190px、列表 340px、阅读区 440px**。窗口变窄时按「账号栏 → 列表 → 阅读区」的顺序依次让位，谁先碰到自己的下限就停下，轮到下一块：

| 窗口宽度（账号栏 264、列表 384 时） | 谁在让位 |
|---|---|
| 1400 → 1100 | 只有阅读区在缩（它是弹性区，正文最宽） |
| 1100 → 1026 | 阅读区已到 440，开始缩账号栏 |
| 1026 → 982 | 账号栏已到 190，开始缩列表 |
| 982 以下 | 三块都到下限，**窗口再也缩不小了** |

- 三栏全展开时的最窄宽度 = 190 + 340 + 440 + 两条分隔线 = **982px**；收起阅读区后 = 190 + 340 + 分隔线 = **536px**（加上窗口边框，外壳拦在 998 / 552）。
- 用 `ikuyoMail.exe` 启动时，窗口的最小尺寸是系统级的（`WM_GETMINMAXINFO`）：拖到边界就停住，手还按着也拖不动，不会先跟着鼠标缩进去、松手再弹回来。从左边框或右边框拖都一样，固定另一侧边缘，窗口不会左右跳。
- 用 `启动 ikuyoMail.bat`（Chrome `--app` 外壳）启动时，由 PowerShell 外壳向页面问这个值，同样会在下限处停住（先 `WM_CANCELMODE` 掐断拖动，再设回下限）。
- 直接用浏览器打开（不经外壳）没有这层保护：窗口窄过上面那个数时，页面底部会浮出一条提示，并给一个「收起阅读区」按钮把下限降下来。
- 列表的 340px 是按「图标 + 主题 + 时间列 + 工具栏按钮」实测出来的：再窄，时间就会被切掉、按钮要换行。

### 窗口拉得很矮时会怎样

高度也有下限：**等于当前最窄宽度的一半**（三栏 499px，收起阅读区 276px，最低不低于 300px），这样工具栏、邮件列表、分页条不会被叠成两行。

- 同样由窗口外壳拦：拖到底边就停住，不会缩成一条缝。
- 页面侧还有一个 44vw 的 `min-height` 兜底（只在 1200px 以下的窄窗口生效，宽屏不会平白多出纵向滚动条）：窗口再矮，内容区保持可排布高度并出现纵向滚动，而不是把按钮压扁。
- 侧栏在很矮的时候会自己滚动，底部「设置」按钮仍然够得着。

### 收起阅读区

- 收起按钮就在阅读区自己的操作栏里（`独立窗口` 旁边的「收起」），或者按 `F9`：界面只剩账号栏 + 邮件列表，列表自动占满右边。
- 列表上不再放「展开阅读区」按钮——点任意一封邮件，阅读区自己就回来了。

### 独立阅读窗口

- 打开一封邮件后，点阅读区顶部的「⧉ 独立窗口」，这封邮件在单独窗口里打开，主界面只剩账号栏和列表。
- 独立窗口里「返回」变成「关闭窗口」；关掉它，主界面自动恢复三栏，并回到你在那个窗口里最后看的那封。
- 主窗口里换着点别的邮件，独立窗口会跟着换。
- 弹窗期间主界面顶部有一条「这封邮件正在独立窗口里显示 · 收回到主界面」的提示，点一下就收回来。

### 贴边抽屉（仅 Windows）

浏览器页面搬不动系统窗口，所以这部分交给 `assets/shell.ps1`：双击 `启动 ikuyoMail.bat` 时它在后台启动，用 Win32 API 直接控制 Chrome / Edge 的应用窗口。

- 以 `--app` 模式打开，没有地址栏和标签栏；用独立的浏览器 profile（`data/app-window-profile`），不打扰你日常浏览。
- 窗口默认贴在屏幕顶部。鼠标离开窗口后，窗口向上滑，只在屏幕顶端留 3px；鼠标移到那 3px 上，窗口滑回原位（进出用同一个缓动，速度一致）。离开后多久收起看你当时在不在用这个窗口：它在前台时等 2.5 秒（免得刚抬手鼠标就滑走），在后台时 0.7 秒。
- 把窗口拖离顶部，或者最大化，就不参与自动收起，和平常窗口一样用；拖回顶部附近又会恢复。
- 从任务栏点回来也会自动滑出，不会出现「点了没反应」。
- 窗口缩到比三栏总和还窄时（约 840px 以下），页面会横向滚动，版面保持不变——不会出现某一块被挤没、另一块内容挤成一团。
- 正常位置记在 `data/shell-window.json`，下次从原处打开；异常退出也会把窗口挪回屏幕内。
- 只要窗口不要抽屉效果：

  ```bash
  powershell -ExecutionPolicy Bypass -File assets\shell.ps1 -NoEdgeHide
  ```

- 想用普通浏览器标签页：直接访问 http://127.0.0.1:7317 就行，只是没有贴边效果。

## 打包成 exe

`ikuyoMail.exe` 是一个原生窗口程序（C# WinForms + WebView2），界面还是同一套页面，只是外壳换了：

| | 双击 `ikuyoMail.exe` | 双击 `启动 ikuyoMail.bat` |
|---|---|---|
| 窗口 | 自己的 WinForms 窗口（WebView2 内核） | Chrome / Edge 的 `--app` 窗口 |
| 最小尺寸 | 系统级 `WM_GETMINMAXINFO`，拖动时就停住 | PowerShell 轮询 + `WM_CANCELMODE` 掐断拖动 |
| 贴边抽屉 | 原生实现，30ms 检测 + 13 步缓动 | `assets/shell.ps1` 驱动 Chrome 窗口 |
| 服务进程 | exe 自己拉起，关窗时一起结束 | shell.ps1 负责 |
| 依赖 | .NET 10 桌面运行时 + WebView2 运行时（Win11 自带） | Node + 本机 Chrome/Edge |

- exe 需要和 `src`、`public`、`node_modules` 放在同一个文件夹里（它会往上找 `src/server.js`，所以放子目录也能认出来）。同目录的 `WebView2Loader.dll` 别删。
- 关窗按设置里的「关闭行为」走：默认只是把窗口藏起来（服务、托盘继续收信），选「退出程序」才连自己拉起的 Node 服务一起停掉。
- 不想自动收起：`ikuyoMail.exe --no-edge-hide`。
- exe 是单实例的：第二次启动（比如托盘菜单的「设置…」）不会开新窗口，而是把参数（如 `settings`）转交给已经开着的那个窗口，并把它叫到前台。
- 窗口大小和位置记在 `data/window.json`，WebView2 的缓存放在 `data/webview2`。

重新构建：

```bash
cd desktop
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o ../dist
cp ../dist/ikuyoMail.exe ../
```

（`-o` 不要直接指向项目根目录：SDK 会把 `obj` 里的中间产物一起算进去，报 CS5001。）

想要一个不依赖 .NET 运行时、可以拷给别人的版本，把 `--self-contained false` 换成 `true`（产物约 150MB）。

### 自检：另存为 PDF 的打印链路

「另存为 PDF」走的是 WebView2 的 `PrintToPdfAsync`，可以用一个命令行入口单独验证（不弹主窗口）：

```bash
# 先开着服务（或开着程序），再执行；结果会写在 out.pdf.result.txt
ikuyoMail.exe --pdf-test="http://127.0.0.1:7317/print.html?acc=<账号id>&folder=INBOX&uid=<uid>|D:\out.pdf"
```

`ok=True` 且 `size` 不为 0 就说明这条链路是通的。

## 安装包（分发给别人）

`ikuyoMail-Setup-1.0.0.exe`（约 126 MB）是给「没装 Node、也没装 .NET」的人用的安装程序：

- **界面**：左边是插画和版本号，右边填安装位置、勾桌面快捷方式，一个按钮装完；配色跟程序本体一致（主色取自插画里的红），无边框圆角窗口。
- **装在哪**：默认 `%LOCALAPPDATA%\Programs\ikuyoMail`，装到当前用户，**不需要管理员权限**；装机位置可以改。选目录时总会落在其下的 `ikuyoMail` 文件夹里（选 `H://` → `H://ikuyoMail`，选 `H://Apps` → `H://Apps//ikuyoMail`；已经选中 `ikuyoMail` 就不再套一层）。
- **装了什么**：自包含的 `ikuyoMail.exe`（不依赖 .NET 运行时）、`Uninstall.exe`（`ikuyoMail.exe` 的硬链接，双击就能卸载）、`runtime\node.exe`、生产依赖、`src` / `public` / `assets`。
- **顺带做了**：桌面 + 开始菜单快捷方式、开始菜单里的「卸载 ikuyoMail」、写入「设置 → 应用 → 已安装的应用」（版本 1.0.0，卸载命令指向安装目录里的 `Uninstall.exe`）。
- 没检测到 WebView2 运行时的话，界面上会直接给下载链接（Win11 和大部分 Win10 自带）。

### 卸载

三种入口都走同一个窗口（确认 → 进度条 → 「卸载完成」）：

- 安装目录里的 `Uninstall.exe`；
- 开始菜单 → ikuyoMail →「卸载 ikuyoMail」；
- Windows「设置 → 应用 → 已安装的应用」→ ikuyoMail → 卸载。

窗口里可以选择「同时删除本机的邮件账号、备注和设置」：不勾就只删程序，`data\`（账号、备注、设置）留着，重装后接着用。

卸载时会先把自己复制一份到 `%TEMP%` 再动手，所以安装目录里一个文件都不会剩下（连 `Uninstall.exe` 自己也被清掉），最后用临时批处理收尾删空目录。

生成：

```bash
node scripts/build-setup.mjs                   # 全量：发程序 → 收运行时 → 压包 → 发安装程序
SKIP_PAYLOAD=1 node scripts/build-setup.mjs    # 只改安装界面时用，跳过前三步（几秒出包）
```

中间产物都在 `build/` 里：`build/app`（自包含 exe）、`build/payload`（要装进去的目录）、`installer/payload.zip`（约 79 MB，作为嵌入资源打进安装程序）。

静默安装 / 卸载（脚本用，也可以自己试）：

```bash
ikuyoMail-Setup-1.0.0.exe /S --dir=D://Apps --log=%TEMP%\setup.log   # 退出码 0 = 成功；装在 D://Apps//ikuyoMail
Uninstall.exe                      # 带界面的卸载
Uninstall.exe /S                   # 静默卸载，保留 data
```

## 设置：图片、提醒、关闭行为与开机自启

点左下角的「⚙ 设置」按钮打开设置（也可以从托盘右键菜单 →「设置…」进入）。设置存在 `data/settings.json`，不含任何凭据。

### 1. 外部图片：默认拦截 / 默认显示

| 选项 | 行为 |
| --- | --- |
| 默认拦截（默认值） | 正文里的远程图片不加载，避免发件人通过追踪像素知道你何时打开邮件 |
| 默认显示 | 打开即加载全部远程图片，适合只收内部邮件的人 |

不管选哪个，阅读区顶部都会有一条提示：拦截时给「显示图片 / 以后都显示」，放行时给「隐藏图片」。**「以后都显示」会直接把设置改成允许**，省得再进设置翻。

### 2. 关闭行为：最小化到状态栏 / 退出程序

| 选项 | 行为 |
| --- | --- |
| 最小化到状态栏（默认） | 关掉窗口后程序继续在后台收信，右下角弹提醒；托盘图标常驻 |
| 退出程序 | 关掉窗口即完全退出，不再检查新邮件，也不会有提醒 |

两个选项都有 15 秒宽限期：刷新页面、跳转、误关后立刻重开，程序不会被判定成"你走了"。

> **用 ikuyoMail.exe 启动时**：这两个选项照样生效。选「最小化到状态栏」，关窗只是把窗口藏起来（服务、托盘、新邮件提醒都还在跑），再双击一次 `ikuyoMail.exe`，或者点托盘图标，窗口就回来了——exe 是单实例的，不会开出第二个窗口。选「退出程序」，关窗就把服务一起停掉，不留后台进程。

### 3. 新邮件提醒

- **检查间隔**：30 秒 ~ 30 分钟，默认 2 分钟。改成多短都不会低于 30 秒（对服务商友好一点）。
- **提示音**：开关；页面内用 WebAudio 合成的两声短音，不依赖音频文件。
- **窗口不在前台时弹系统通知**：勾上后，如果窗口最小化 / 被其他程序盖住 / 已经关闭，会用 Windows 右下角的气泡通知提醒你，点气泡直接打开信箱；窗口在前台时只弹页面内卡片，不会重复打扰。
- **发一条测试提醒**：立刻验证整条链路，不用等真邮件。

提醒的判定逻辑：每个账号在 `data/notify-state.json` 里记一个 **UID 水位线**，只把水位线之后的新 UID 当作新邮件。第一次接入某个账号时只记录水位线、不弹历史邮件，所以加号进去不会被 965 封旧信炸屏。

托盘图标是 `assets/tray.ps1` 起的常驻 PowerShell 进程（Windows 原生 `NotifyIcon`），Node 通过一个命令文件跟它通信，不依赖任何需要编译的原生模块。

> **说明**：这是一个浏览器里跑的 Web 界面，"关闭窗口" 无法被网页本身拦截。程序的做法是监听页面与服务之间的长连接，断开后按设置决定是否退出。所以建议双击 `启动 ikuyoMail.bat` 或双击托盘图标打开，而不是随手开个新标签页——效果一样，只是托盘入口用 `--app` 模式打开，没有地址栏，更像一个客户端。

### 4. 开机自启

开关打开后，会在 Windows 的「启动」文件夹里放一个 `ikuyoMail.vbs`（内容只有三行：切到项目目录、用隐藏窗口启动 `node src/server.js`）。登录 Windows 时系统自动执行它，程序会在后台静默跑起来，托盘图标出现在通知区域，不会弹黑框。

- 用的 node 优先取系统安装的 `C:\Program Files\nodejs\node.exe`，没有才回落到当前运行的这个。
- 关掉开关 = 删掉那个 vbs，不写注册表、不留残余。
- 开关状态读的就是「文件在不在」：手动删掉文件后，下次打开设置会显示为关闭。


## 各邮箱怎么拿到"密码"

绝大多数邮箱不接受登录密码，需要单独生成一个「客户端授权码 / 应用专用密码」，填在密码框里。

| 邮箱 | 需要什么 | 在哪里拿 |
| --- | --- | --- |
| QQ 邮箱 | 16 位授权码 | 网页版 → 设置 → 账号 → 开启 IMAP/SMTP → 按提示发短信获取 |
| 腾讯企业邮 | 客户端专用密码 | 管理后台 → 设置 → 客户端专用密码 |
| 163 / 126 / yeah.net | 客户端授权密码 | 网页版 → 设置 → POP3/SMTP/IMAP → 开启 IMAP → 设置授权密码 |
| Gmail | 应用专用密码（16 位） | Google 账号 → 安全 → 开启两步验证 → 应用专用密码 |
| Outlook / Hotmail | 应用密码 | 账号 → 安全 → 高级安全选项 → 开启双重验证 → 创建应用密码 |
| iCloud | App 专用密码 | appleid.apple.com → 登录与安全 → App 专用密码 |
| Yahoo | 应用密码 | 账号安全设置 → 生成应用密码 |
| 新浪 / 阿里云 | 一般用登录密码 | 需先在设置里开启 IMAP/SMTP 服务 |

填写时选对服务商，IMAP / SMTP 主机和端口会自动带出；特殊服务商可以展开「高级：自定义服务器」手填。

添加账号时，邮箱地址被拆成 **用户名 @ 域名** 两段。选定服务商后域名会自动锁定（比如选「网易 163 邮箱」，域名立刻变成 `163.com` 且不可编辑），你只填 @ 前面的部分。选「自定义 / 其他」时域名可编辑；手动输入 `163.com` 这类已知域名，会自动切到对应服务商。

## 搜索为什么不用 IMAP SEARCH

一开始搜索是直接发 `UID SEARCH OR SUBJECT/FROM/TO` 给服务器的，结果在网易 163 上永远返回 0 封——但服务器回的是 `OK`，不是报错。抓包确认过：Coremail 对 `FROM / SUBJECT / TO / TEXT` 一律回 `* SEARCH`（空列表）再回 OK，只有 `ALL` 和 UID 区间是准的。

所以现在改成**本地索引**：

1. 打开某个文件夹时，后台按「新 → 旧」把信封（主题、发件人、收件人、日期、旗标、大小）分批取回来，缓存在内存里（每个文件夹最多 5000 封）。
2. 搜索时在本地做大小写不敏感的多关键词匹配（空格分隔，全部命中才算），因此中文、邮箱地址、发件人名字都能搜到。
3. 索引没建完也会先给已扫到的结果，列表顶部显示「正在检索更早的邮件 500 / 965」，边扫边刷新；后台抓取会让路给读信、翻页这类前台操作。
4. 新邮件、标已读、删除都会同步进索引，不用等下次重建。

代价是首次进入某个文件夹会多花一点时间在后台（服务端归档里的旧邮件每批要几秒），但搜索本身是毫秒级，也不再受服务商 SEARCH 实现的影响。

## 用代理收发信（只对单个账号生效）

有些邮箱在本地网络连不上（Gmail 最典型），但机器上有代理。这时可以让**指定账号单独走代理**，其他账号依旧直连。

添加或编辑账号 → 展开「代理服务器」：

| 字段 | 说明 |
| --- | --- |
| 协议 | SOCKS5 / SOCKS4 / HTTP / HTTPS |
| 主机 / 端口 | 支持域名、IPv4、IPv6（IPv6 直接写 `::1`） |
| 用户名 / 密码 | 代理需要认证时填，可留空 |

填了主机就会自动勾上「启用代理」。IMAP 与 SMTP 分别通过 `imapflow` 和 `nodemailer` 的 `proxy` 选项走代理，两者用的是同一份配置。

代理密码与邮箱口令一样以 AES-256-GCM 加密保存，接口对外只返回「是否已设置密码」，不会回传明文。

**实测**（`scripts/test-proxy.js`，本地起 SOCKS5 / HTTP 代理，连真实 `imap.163.com`）：

```
SOCKS5 无认证      → IMAP 登录成功，965 封
SOCKS5 带认证      → IMAP 登录成功
HTTP CONNECT       → IMAP 登录成功
SOCKS5 + SMTP      → 认证通过
代理端口未监听      → 正确失败，返回中文提示
代理密码错误        → 正确失败
```

**已知限制**：SOCKS 代理密码里如果有 `@ : / %` 或空格，imapflow 传给 socks 库的是 percent-encode 后的字符串，认证会失败。这种情况改用 HTTP 代理（走 Basic 头，正常解码），或给代理设一个只含字母数字的密码。表单里输入这类密码会当场提示。

## 邮件数量比网页版少？（163 / QQ 常见）

**现象**：网页版收件箱 393 封，客户端里只有 6 封，而且「订阅邮件」「已发送」也全是空的。

**真实原因（2026-10 实测确认）**：不是服务商限制，也不是读取逻辑写错，而是 **IMAP 会话陈旧**。

网易 163 用的是 Coremail，它在 **IMAP 会话建立的那一刻**对邮箱状态做快照。如果这个会话是在你把「收取范围」改成全部邮件**之前**建立的，它会一直返回旧数字（6 封），无论你在网页端怎么改。用一条全新连接去查同一个账号，立刻就能拿到 965 封 —— 这一点我用 `scripts/diag-imap.js` 直接对比验证过：

```
旧会话（复用的连接）  → SEARCH ALL =   6
新连接（重新握手）    → SEARCH ALL = 965
```

**所以正确的操作顺序是**：网页版改完「收取范围 = 全部邮件」→ 回到客户端 → **点刷新（会强制重新握手）**。

程序为此做了四层保护，正常情况下你不需要手动处理：

| 机制 | 说明 |
| --- | --- |
| 连接空闲 60 秒即断开 | 陈旧会话不会长期驻留 |
| 连接绝对寿命 10 分钟 | 活跃使用也会定期重建 |
| 刷新按钮强制重连 | 每次刷新都重新握手，拿服务端最新状态 |
| 诊断自动对比 | 同时用旧会话和新连接各查一次，数字不一致就标记「会话陈旧」并自动丢弃旧会话 |

另外，当服务端报告的总数大于当前能读到的数量时，列表上方会弹出黄色提示条并给出「重新连接并刷新」按钮。

如果诊断显示三个数字一致（例如都是 965），说明服务端确实只有这些，少的邮件可能被 163 的「来信分类」规则分到了别的文件夹，在左侧列表里翻一下即可。

## 已知限制（实话实说）

- 贴边抽屉只在 Windows 上生效（依赖 Win32 API）。用 exe 时是原生实现；用 bat 时依赖 Chrome / Edge 的应用窗口。

- **exe 需要 .NET 10 桌面运行时**（这台机器装了 .NET SDK 就有）。要拷给别人用，用 `--self-contained true` 重新发布，产物会大到 150MB 左右但不再依赖运行时。

- **Outlook / Hotmail**：微软正在逐步停用基础认证，应用密码在部分账号上已被拒绝。若提示登录被拒绝，不是程序 bug，是服务商策略；本程序暂未接入 OAuth2（需要自建 Azure 应用并走授权跳转）。
- **Gmail**：需要你的网络能直连 `imap.gmail.com`，否则会报连接超时。
- **不支持 OAuth2 登录**，全部走「账号 + 授权码」的方式，好处是不用申请开发者应用。
- 单账号同一时间只保持一条 IMAP 连接（浏览器端操作串行），够个人使用，不适合多端同时高频操作。
- **SOCKS 代理密码**含 `@ : / %` 或空格时，底层库无法正确传递，认证会失败；改用 HTTP 代理或换一个纯字母数字密码即可（详见上文「用代理收发信」）。
- 有些服务商不返回 `STATUS ... UIDNEXT`（163 就是），诊断里这一项会显示为 `—`，不影响使用。
- 附件上限约 20MB（受各家邮件服务商限制），超大附件请用网盘链接。
- **托盘与系统通知是 Windows 专属**（用 PowerShell + WinForms 实现）。macOS / Linux 上不会起托盘，关闭行为自动按「退出程序」处理，页面内的右下角提醒仍然可用。
- 收新邮件靠**轮询**而不是 IMAP IDLE：网易等服务器对长连接空闲时间有限制，轮询更稳。代价是最长要等一个间隔（默认 2 分钟）才会提醒。
- 提醒只在**收件箱**上生效，被规则分到其他文件夹的邮件不会触发提醒。

## 安全说明

- 服务只绑定 `127.0.0.1`，不对外网开放。
- 授权码用 AES-256-GCM 加密后存于 `data/accounts.json`，密钥是 `data/.secret`（首次启动自动生成，权限 0600）。
- 每次改动账号都会在 `data/backups/` 留一份快照（保留最近 12 份，内容同样加密），误删账号可以从这里找回。
- 联系人只存地址和名字（`data/contacts.json`），不含邮件内容，同样只在本机。
- **`data/` 目录等同于你的邮箱钥匙**：不要提交到 git、不要发给别人。换电脑时重新登录即可，不必拷贝。
- 邮件正文在 `sandbox` iframe 中渲染，禁用脚本，并默认拦截远程图片（防追踪像素）；是否默认放行由设置决定。
- 写信时粘贴的内容会先过一遍白名单清理，去掉脚本和事件属性。
- 如果环境里有 `NODE_TLS_REJECT_UNAUTHORIZED=0`，Node 会全局关闭证书校验，启动时会打印警告。本程序对每台服务器单独指定 `rejectUnauthorized`，但仍建议去掉该变量。
- 这是个人自用工具，没有做多用户隔离、CSRF 防护等公网级加固。请勿把它暴露到公网。

## 常见问题

**提示"登录被拒绝"**
先确认填的是授权码而不是登录密码，再去网页版确认 IMAP 服务已开启。QQ 邮箱如果频繁重试会被临时限制，等 10 分钟再试。

**提示"连接服务器超时"**
多半是网络问题（Gmail 尤其），或者公司网络封了 993/465 端口。可以先用手机热点试一下。

**证书错误**
少数自建邮件服务器用的是自签证书，在添加账号的「高级」里勾选「忽略证书错误」即可。

**中文显示成乱码**
正文由服务端的 `mailparser` 按 `Content-Type` 里的 charset 转换（支持 GBK/GB18030），正常邮件不会乱码。若某封邮件本身没声明字符集，可能显示异常。

**改了授权码怎么办**
点账号右边的 ⚙ 打开账号设置，填新的授权码保存即可（会重新验证，验证不过不会覆盖原配置）。换邮箱地址则需要删除后重新添加。

**邮件数量比网页版少**
见上面「邮件数量比网页版少？」一节。

**收不到新邮件提醒**
按顺序排查：设置里「收到新邮件时提醒我」是否勾上 → 托盘图标有没有出现（被折叠进 `^` 里时容易看漏）→ 点「发一条测试提醒」看页面右下角有没有卡片 → 再确认检查间隔不是 30 分钟。如果页面卡片有、系统通知没有，检查 Windows 的「专注助手 / 勿扰模式」是否开着，它会拦掉所有气泡通知。

**提醒只在收件箱生效**
被 163 的「来信分类」分到「订阅邮件」「广告邮件」的邮件不会触发提醒。需要的话可以在左侧手动点进那个文件夹，把规则改掉。
